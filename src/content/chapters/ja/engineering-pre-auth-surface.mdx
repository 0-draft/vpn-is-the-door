## ログイン画面より手前は誰にでも応答する

図5-2で1つの接続を上から追う。機器は TLS を終端し、Web デーモンが要求を読んで処理先に振り分ける。FortiOS ではこのデーモンが `sslvpnd` で、Fortinet は CVE-2022-42475 の勧告でこのプロセスを名指ししている（[FG-IR-22-398](https://www.fortiguard.com/psirt/FG-IR-22-398)）。網掛けの範囲はすべてこの段階で動く。ログイン画面、画面が読み込む静的ファイル、VPN クライアントの配布、SAML や SSO の受け口、クライアントレスの Web 接続、そして多くの環境では管理画面である。パスワード、第2要素、SAML アサーションの確認は、この範囲を抜けた後にしか行われない。

認証前の欠陥はこの範囲の中にある。図の赤線は悪用されたときの流れを示す。要求は Web デーモンから OS に渡り、認証の箱を通らずに社内へ届く。多要素認証の設定はこの流れに関係しない。[建具表](../../the-doors/)に載せた KEV 登録済みの VPN・リモートアクセス製品の CVE {TOTAL}件のうち、{PREAUTH}件はログイン前に到達できる。残る{TOTAL - PREAUTH}件も、実際の攻撃ではログイン前に到達できる欠陥と組み合わせて使われた。

## 相手が誰か分かる前にこのコードは動く

認証前のコードは誰からの入力でも受け付けなければならない。アカウントごとの制限も、送り手の身元も当てにできない。多くの SSL-VPN 製品では、ログイン画面とログイン後のポータルを同じ Web 処理系が担う。その処理経路のどこかに欠陥があれば、インターネットから届く。

図5-3は、建具表の{TOTAL}件の CVE を欠陥の種類で分けたものである。最も多いのはメモリ破壊である。大半はバッファオーバーフローと範囲外の読み書きで、解放後使用（use-after-free）が1件ある。この種の欠陥は C や C++ のようなメモリ安全でない言語で書かれたコードで起きる。CISA と FBI は、バッファオーバーフローの例に CVE-2025-0282（Ivanti Connect Secure）と CVE-2023-6549（Citrix NetScaler）を挙げ、「Threat actors frequently exploit these vulnerabilities to gain initial access to an organization's network and then move laterally to the wider network.」と書いた。この種類は「can be addressed by using memory safe languages」とも述べている。こうしたコードの多くが1つの大きな Web デーモンに収まった古い C であるという見方は、欠陥の種類と Pulse Secure から Ivanti に至る製品系譜から本サイトが推測したものである。ベンダーはこれを公表していない。

## 自社のアドレスに限って外から露出を棚卸しする

まず自社が持つものから始め、次にインターネットからどう見えるかを確かめる。以下の方法はすべて、自社に属するアドレスと名前だけを対象にする。自社が管理していないアドレスを走査したり探ったりしてはならない。事業者やベンダーが自社のために運用している範囲を走査するときは、事前に書面で許可を得る。

<div class="table-scroll" tabindex="0">

| 方法 | 分かること | 分からないこと |
| --- | --- | --- |
| 資産台帳と契約書 | インターネットに面した全機器。保守のためにベンダーが設置した機器も含む。大阪急性期・総合医療センターの事案は給食事業者の機器から入られた（p.45） | 誰も記録しなかった機器 |
| 自社のグローバル IP 範囲の走査（自社または契約した診断事業者が実施） | 応答するポート、ポータルや TLS 証明書から分かる製品と版 | 一覧に入れ忘れた範囲 |
| Shodan や Censys など公開情報の検索エンジン（自社の範囲とドメインで検索） | 外部の走査ですでに記録された自社の姿と、その履歴 | まだ収集されていないもの |
| 自社ドメインの証明書透明性（CT）ログ | `vpn.example[.]com` のように、誰かが立てて忘れたホスト名 | IP アドレスだけで使っている機器 |
| ベンダーのサポートポータル | 機種、シリアル番号、サポート終了日 | 以前の委託先名義で登録された機器 |

</div>

## 応答しなくてよいものは止める

図5-4は面を削った後の同じ機器である。どの変更も、網掛けの範囲の一部をインターネットから届かなくする。有効なまま残る処理に欠陥があれば直らないので、パッチは引き続き必要である。

<Fig lang="ja" n="5-4" caption="同じ機器で、管理画面をインターネットから外し、使わない機能を止め、手前に接続元 IP の制限を置いた状態" sources={["cccs-itsm-80-101", "handa-report-tech", "ch5-jpcert-at-2024-0004"]} nts>
  <PreauthLifecycle lang="ja" variant="reduced" label="図5-2と同じ機器。手前の緑の線は接続元 IP の制限。クライアントレスは無効化、管理画面はインターネットから外したことを示す取り消し線。赤い経路はない。" />
</Fig>

<div class="table-scroll" tabindex="0">

| 変更 | 認証前の範囲から外れるもの | 根拠 |
| --- | --- | --- |
| 管理画面を別の管理用ネットワークに移す | 管理用 Web 画面とその API | CCCS は管理インターフェースを「should not be directly exposed to the Internet.」としている |
| 利用者が固定の拠点から接続する場合、ポータルへの接続元アドレスを限定する | 一覧外の相手から見た全処理 | 半田病院の機器には接続元の制限がなく、「インターネット上のすべてのシステムからの接続が可能であった。」（技術編 p.11）。移動する利用者の接続元は固定できないため、取引先や拠点間の接続に向く |
| 使っていない機能を止める（クライアントレス接続、使っていない SSO 連携、古いプロトコル版） | その機能の裏にあるコード | CCCS は「Deactivate any functionality that is not required.」と求めている。CVE-2026-24858 の影響を受けたのは FortiCloud SSO を有効にした機器だけだった |
| 未修正の KEV がある間の応急策として、SSL-VPN 機能自体を止める | ポータル全体 | JPCERT/CC は CVE-2024-21762 について「SSL VPN機能を無効にすることで本脆弱性の回避が可能です。」としている |

</div>
