# 扉はVPNだった

[English](README.md) | **日本語**

2025年、侵入経路が判明した国内のランサムウェア被害92件のうち61件は VPN 機器からの侵入だった。不審メールは2件にとどまる。このサイトは、架空の会社1社の平面図を使ってその理由を示す。経営層向けの要旨から、技術者が見るべきログまでを扱う。

**読む:** <https://0-draft.github.io/vpn-is-the-door/ja/>（English: <https://0-draft.github.io/vpn-is-the-door/>）

## 構成

題材は従業員280人の部品メーカー、港精密株式会社（Minato Precision Co., Ltd.）。本社を建築の平面図で描き、VPN 機器は「社員が受付を通らずに外から入るために外壁に付けた扉」として表す。すべての章が同じ図面に戻ってくる。

章は事案が進む順に並ぶ。

| # | 章 | 内容 |
| --- | --- | --- |
| 0 | 要旨 | 建物の上に描いた統計（被害1件を四角1つで表す）。 |
| 1 | 侵入口 | 警察庁が何を数えたか、開口部ごとの件数、2021〜2025年の推移。 |
| 2 | 扉が開いた後 | 扉から暗号化までの経路をスクロールで追う平面図、所要時間、病院の調査報告書との対応。 |
| 3 | 建具表 | 製品と扉の詳細図、KEV に登録された31件の脆弱性を絞り込める一覧。 |
| 4 | 事例 | 組織自身が侵入経路を公表した事案。経過表付きの短い報告書として1件ずつ。 |
| 5 | 技術者向け | ログイン前に到達できる範囲、パッチだけでは扉が閉まらない理由、再起動で失われる証拠。 |
| 6 | 再発防止策 | 担当者別の対策と、各対策が効く地点でだけ経路を断つサンドボックス。 |

## 数字の根拠

- 警察庁の統計は、警察庁が公開している統計データ（`*_jousei_data.xlsx`）からシート名付きで引いている。割合は `src/data/stats.ts` の1か所で計算し、警察庁が公表した丸めた値と一致することを単体テストで確かめている。
- 脆弱性は、CISA の Known Exploited Vulnerabilities カタログ（2026.10.23 版）と項目ごとに照合した。KEV でランサムウェア利用が「Unknown」のものは「不明」と表示し、「なし」とは書かない。
- 事例は、組織自身の発表か公式の調査報告書だけを根拠にしている。組織が「ネットワーク機器」とだけ述べている場合は、VPN と書かずに「ネットワーク機器」と書く。
- 港精密は架空の会社で、登場する図には必ず複合事例と明記している。実在の事例には混ぜない。
- 一次情報で確認できなかったことは載せていない。除外した項目とその理由を含む調査メモは [`research/`](research/) にある。

攻撃コード、ペイロード、攻撃手順はどこにも載せていない。脆弱性は種類の説明にとどめ、ベンダーのアドバイザリにリンクしている。

## 開発

Node.js 24 以上と pnpm 12 が必要。

```bash
pnpm install
pnpm dev                 # http://localhost:4321/vpn-is-the-door/
pnpm build               # dist/ に静的サイト、dist/og/ に OG 画像、続けて dist/pagefind/ に検索索引を出力
pnpm preview             # GitHub Pages と同じく /vpn-is-the-door/ 配下で dist/ を配信
pnpm lint                # Biome
pnpm check               # astro check
pnpm test                # Vitest（データ、図形、操作ロジック）
pnpm test:e2e            # Playwright + axe（デスクトップとモバイル。先に pnpm build）
pnpm validate:data       # 出典、参照、英日テキストの検査
pnpm perf                # Lighthouse（モバイル、3回の中央値）で予算を検査（先に pnpm build）
```

| パス | 内容 |
| --- | --- |
| `src/content/chapters/{en,ja}/` | 本文（MDX）。英語版と日本語版は同じスラッグ、節、図を持つ。 |
| `src/data/` | 統計、脆弱性、事例、用語集、各図が参照する出典一覧 `sources/*.json`。 |
| `src/lib/plan.ts` | 平面図の座標。デスクトップ用とスマートフォン用の2レイアウト。侵入経路が扉以外で壁を通らないことを単体テストで確かめている。 |
| `src/components/` | 平面図、スクロール図、建具表、サンドボックス、図と出典の部品。 |
| `research/` | 出典調査とデザインの決定記録。 |

## CI とデプロイ

`.github/workflows/ci.yml` は Biome、markdownlint、`astro check`、カバレッジ付きの Vitest、データ検査、`pnpm audit`、プルリクエストでの依存関係レビュー、ビルド、明暗両テーマ・デスクトップとモバイルでの Playwright + axe、`#フラグメント` まで確かめるオフラインのリンク検査、5ページの Lighthouse（performance 0.9 以上、accessibility 1、CLS 0.05 以下、ページごとの転送量の上限）、ワークフローの actionlint + zizmor を実行する。日本語フォントはビルド時にサイトで使っている文字だけに絞り、言語と太さごとに1ファイルにしている。絞った結果に無い字形をページが必要とした場合はビルドが失敗する。CodeQL は push のたびと毎週実行する。Dependabot は毎週月曜に npm と Actions の更新を提案する（7日間のクールダウン付き）。`kev-drift.yml` は毎週月曜に建具表と KEV の最新版を照合し、掲載済みの行が変わったときや調べるべき新しいリモートアクセス製品の登録があったときに issue を1件立てて更新する。行を自動で追加することはしない。Actions はすべてコミット SHA で固定している。pnpm は公開から2日未満のパッケージを受け付けない（`pnpm-workspace.yaml` の `minimumReleaseAge`）。Lighthouse のジョブは版を固定した Chrome for Testing で動かす。

`main` への push は、すべての検査に通ったときだけ GitHub Pages に公開される。
